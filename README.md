# 小报告插件

由 bot 结合聊天上下文判断是否需要管理员介入，向指定管理员私聊、管理群，或同时向两处转发相关原消息，再通过正常回复流程汇报情况。

## 使用前确认

- 使用 MaiBot 1.3.x，版本至少为 1.3.6。
- QQ 适配器支持合并转发。
- 私聊收件人能够收到 bot 的私聊消息；使用管理群时，bot 已加入该群并有发言权限。
- 希望收到小报告正文时，接收聊天需要允许 bot 正常回复，回复频率不能设为 `0`。

**插件默认关闭。当前版本尚不能严格保证举报证据只来自当前聊天，存在误转发其他聊天消息的风险；涉及敏感聊天记录时，请谨慎启用。**

## 安装和启用

1. 将插件目录放入 MaiBot 的 `plugins/` 文件夹，最终路径为 `plugins/report_to_admin_plugin/`，然后在 WebUI 的插件管理中加载插件。
2. 首次加载后，插件目录中会自动生成 `config.toml`，无需提前创建配置文件。
3. 在 WebUI 中打开插件配置，按下表选择投递方式，填写对应的管理员 QQ 或管理群号。
4. 确认收件人、群聊可见范围及上面的使用风险后，将 `plugin.enabled` 设为 `true` 并保存。

| 投递方式 | `report.private_enabled` | `report.group_enabled` | 需要填写 |
| --- | --- | --- | --- |
| 只发管理员私聊 | `true` | `false` | `report.admin_qq` |
| 只发管理群 | `false` | `true` | `report.admin_group_id` |
| 同时发到两处 | `true` | `true` | 管理员 QQ 和管理群号 |

至少开启一种投递方式。收件人固定使用配置中的号码，不会由聊天中的其他人临时指定。

配置示例如下，号码仅用于举例，请替换为实际收件人。示例保持插件关闭，确认配置后再将 `enabled` 改为 `true`。

```toml
[plugin]
enabled = false
config_version = "1.2.0"  # 保留自动生成的值，无需修改

[report]
private_enabled = true
admin_qq = "123456789"  # 管理员 QQ，替换为实际号码
group_enabled = true
admin_group_id = "987654321"  # 管理群号，替换为实际群号
cooldown_seconds = 60
max_reports_per_hour = 20
dedup_seconds = 86400
```

## 如何使用

启用后无需发送固定命令。bot 在聊天中遇到明确的辱骂、威胁或持续骚扰，并认为需要管理员介入时，可以发送小报告，包括 bot 自己被骚扰的情况。

普通玩笑、相互调侃、引用讨论、意见不合以及无法确定的情况，不应被举报。是否发送由 bot 根据当时的上下文判断，不保证发现所有不良消息，也可能判断有误，请由管理员核实。

小报告正文使用 MaiBot 原有的正常回复流程和模型配置，无需新增模型设置。管理员不需要先向 bot 发消息；即使是新建的接收聊天，也可以在收到转发证据后进入汇报流程。插件不会自动撤回消息、禁言或处罚任何人。

## 管理员收到什么

每次举报最多包含 5 条原消息，按发送时间排列。每个启用的收件目标先收到包含原发送者和原内容的合并转发，再由 bot 尝试生成小报告，说明已知事实及需要管理员介入的原因。

同时启用私聊和管理群时，两处使用相同的事实和证据，但 bot 会结合各自聊天的人设、关系及上下文表达，小报告的口吻和正文可以不同。

**证据已转发、汇报任务已排队，不等于小报告正文已经送达。** bot 的正常回复流程可能决定不回复，接收聊天的回复频率为 `0` 时也不会生成汇报。即使正文已发送，也不表示管理员已经确认或处理。

**发到管理群的小报告对该群所有成员可见，并非只有管理员可见。** 管理群可以设为原消息所在群，此时小报告会直接公开发送到原群，请确认这是你希望的投递范围。

## 频率和重复消息

| 配置项 | 默认值 | 使用说明 |
| --- | --- | --- |
| `report.cooldown_seconds` | `60` | 同一个群聊或私聊两次新举报的最短间隔，单位为秒；设为 `0` 可关闭此间隔限制 |
| `report.max_reports_per_hour` | `20` | 所有聊天合计每小时的举报次数上限，同时发到私聊和管理群只算一次 |
| `report.dedup_seconds` | `86400` | 同一批举报的防重复时长，单位为秒；默认 24 小时 |

在防重复记录保留期间，同一批证据不会重复转发，已排队的汇报任务不会重复提交，新的举报也不能夹带已经举报的消息。插件最多保留最近 1024 批举报记录；bot 重启、插件重新加载或卸载后，记录会清空。防重复记录不用于判断小报告正文是否已经送达。

证据已经转发、但汇报任务尚未排队时，可以请 bot 重试同一批消息，只继续未完成部分，无需重新等待冷却，也不额外占用一次举报额度。

## 常见问题

### 为什么没有发送小报告？

先确认插件已启用，至少开启一种投递方式，且对应 QQ 或群号填写正确。再检查 bot 能否向该账号私聊，或是否已加入管理群且能发言；插件不会绕过 QQ 的好友、入群、禁言或风控限制。

配置正常但没有报告时，可能是 bot 没有判断为需要举报，或触发了冷却、每小时数量限制、重复消息限制。可查看插件日志中的失败原因；管理员和 bot 自己发送的消息不能举报。

### 为什么收到证据，却没有小报告正文？

请先确认接收聊天没有暂停回复，回复频率也不为 `0`。小报告通过正常回复流程生成，bot 仍可能决定暂不回复。

插件只能确认汇报任务是否已经排队，不能确认后续正文是否生成或送达。任务尚未排队时，可以重试同一批消息；已经排队后，不会因未看到正文而重复提交任务。请结合 bot 日志和实际收件情况检查后续回复是否失败，不要把“已排队”当作“已送达”。

### 一边收到了，另一边没收到，怎么办？

私聊和管理群分别处理，一边失败不会阻止另一边继续。先恢复未收到一边的私聊或群聊权限，再请 bot 重试同一批消息。已转发的证据不会重发；汇报任务尚未排队的目标继续安排，已排队的目标不会再次提交任务。

插件不会定时自动重试，也不会缓存一份固定正文等待补发。如果两处都已收到证据且任务已排队，只是其中一处没有正文，请按上一项检查。若 QQ 已收到证据但发送结果没有及时返回，再次尝试仍可能造成重复，请先查看实际收件情况。

### 为什么提示原消息或原始媒体不可用？

找不到原消息，或者原消息中的图片、表情、语音文件已经丢失时，插件不会发送这份证据，也不会用文字描述冒充原图或原语音。请改用仍能读取原内容的消息；如果之前已成功转发证据，但汇报任务尚未排队，仍可尝试继续安排汇报。
